# 供应商管理

入口：平台首页 → 供应商管理。前端页面无外部依赖；共享版通过本机 Python 服务打开。

目前资源库为空；没有预置或虚构供应商数据。新增、编辑、批量导入后，总览、画像、匹配和梯队复核自动更新。共享版数据保存在 `data/suppliers.sqlite3`。多个浏览器访问同一个本机服务共享资料，并每 8 秒检查更新；正在编辑时延后刷新。直接打开旧 `file://` 页面仍是 localStorage（`jst-suppliers-v1`）本地版，请导出后迁入共享版。JSON 备份包含供应商、评分权重和梯队；导入备份时恢复规则与梯队，供应商按 ID 合并。

## 数据接入

页面提供 CSV 空模板；支持 UTF-8 CSV、JSON 对象数组以及导出的版本 1 备份。名称、ID、类型必填，其他指标允许为空。批量导入逐行校验，整批通过后按 ID 新增或替换，替换时空值也会覆盖旧值。自定义供应商类型可通过导入扩展，分类筛选自动识别。当前标准分类为加工、外采、面料。

字段定义见 `supplier-core.js` 的 `fields`。CSV 列名采用字段键；品类 `categories` 用 `/` 分隔，同时兼容旧版 `|`。`extra` 为任意 JSON 对象，用于后续增加字段；`categoryRatings` 是各品类专业程度评分的 JSON 对象（0–100）。两类 JSON 单元格按 CSV 标准使用双引号包围，并将内部双引号重复转义。面料数量单位为米，工厂数量单位为件；导入前统一口径。`supplyScale` 可记录其他规模及单位。

## 匹配规则

先验证登记品类、合作准入状态、最低起订量、有效期内实际可用产能；根据输入增加类型、地区、交付日期、最高单价和员工规模条件。明确失败为“不满足条件”；无失败但存在缺失、过期或需要预留确认的信息为“待核实”；所有硬性条件有数据且符合才为“满足条件”。有效日期按本地日历计算；产能核实日期不得晚于今天，有效期至少覆盖今天。指定交付日期时，有效期还需覆盖交付日期。理论日产能由 `dailyCapacityMin` 下限和 `dailyCapacityMax` 上限记录，允许单侧为空，下限不得大于上限；画像展示范围。旧版 `dailyCapacity` 单值保留为参考，不推断上下限，编辑时提示核实范围。理论日产能范围不用于实际承接判断。

评分与硬性条件分开。默认权重为品类专业程度 25、交付稳定性 25、质量 20、成本竞争力 15、配合程度 10、合作优先级 5，可在页面修改。品类专业评分只读取 `categoryRatings[需求品类]`，不会用通用品类评分替代具体品类能力。所有评分必须同时存在 `evidence` 评估依据才参与加权平均。缺失指标不补零，展示评分和权重覆盖度；缺失评分的满足条件资源仅表示硬性条件符合，不表示综合能力优秀。雷达图和数值列表展示所有实际录入的评分；没有评估依据时使用香槟色虚线并提示“依据待补充”，不会隐藏已录入分数，但仍不参与需求匹配综合评分。缺指标时只绘制已有点，不补全虚构多边形。

“采用当前匹配”最多选择四家满足条件的资源，并保存当时需求。手动梯队绑定订单后也必须满足硬性条件；不绑定订单的品类梯队提示待核实承接条件。资料或权重更新实时复核既有梯队，标注失效条件，不擅自替换人工维护的合作关系。评分仍是辅助判断，产能预留需业务确认。

## 验证

运行 `node modules/suppliers/supplier-core.test.cjs`。测试夹具仅在 Node 中用于验证，不进入页面数据。页面本身与同名 CSS/JS 复制到 `docs/modules/suppliers`；首页入口分别位于根目录与 docs。


## 合作品牌

`brands` 记录合作品牌，支持周淼、鹭青一多选，不依据其他字段推断。旧资料缺少品牌时归为“待完善”；CSV 可填 `周淼/鹭青一`（兼容 `|`），JSON 使用字符串数组。新增和编辑表单用复选项，取消所有选项保存为空。导入校验品牌名称并去重。

供应商管理主页展示两个品牌的资源数及专供 / 多品牌合作数。品牌统计有交叉，供应商总数仍按 ID 去重，禁止把品牌卡片数量相加作为总数。点击卡片可进入资源库按品牌筛选；标签同时展示在资源列表和产能画像中。

需求匹配可选品牌：已登记品牌包含需求品牌时通过，不包含时不满足该合作品牌条件，缺失时待核实。此判断只反映当前登记的合作关系，不推断供应商未来拓展品牌的能力。梯队保存对应需求品牌并复核；现有梯队仍按品类维护，采用另一品牌的同品类匹配会替换该品类梯队。

停用品牌的旧关联仅保存在 `retiredBrands` 备份字段中，不进入标签、品牌统计、筛选与推荐；供应商记录本身保留。旧梯队绑定已停用品牌时提示重新匹配。


## 共享版启动与迁移

双击项目根目录的 `启动共享平台.vbs`，自动启动后台服务并打开主页。也可执行 `powershell -NoProfile -ExecutionPolicy Bypass -File start_supplier_platform.ps1`。服务已启动时重复执行会复用。

所有浏览器使用 `http://127.0.0.1:8765/index.html`，供应商入口为 `/modules/suppliers/index.html`。重启电脑后再次双击启动文件。服务只监听本机回环地址，不向局域网开放。

旧资料只需迁移一次：在原谷歌浏览器的 `file://` 供应商页面导出 JSON，打开共享版后批量导入并确认。旧版页面也提供“导出旧资料并打开共享版”按钮。旧 localStorage 保留，不会自动删除或覆盖。导入按 ID 更新，有冲突的旧记录会完整替换共享库同 ID 记录，请核对预览。

供应商、规则权重和梯队统一保存。API 保存使用版本校验，发现其他浏览器已保存时返回冲突、读取最新资料，并保留当前表单供核对重试；网络失败不会假报保存成功或偷偷回退到本地存储。SQLite 自动保留最近 50 次修改前快照，平时可用页面导出 JSON 备份。服务日志位于 `data/supplier-service`。

验证共享持久化及同时保存冲突：`python -m unittest test_supplier_server -q`，测试仅使用临时数据库，不写真实共享库。


## UI / UX 工作台升级

桌面资源库与画像按 32% / 68% 展示；900px 以下改为上下布局，600px 以下画像 KPI 为两列，雷达图与评分条上下排列。资源库采用紧凑卡片，可按品牌、类型、品类和合作状态组合筛选；列表独立滚动。短屏幕取消资源库吸顶，避免控件被遮挡。

画像保留所有既有字段，按资质、生产资源、工艺能力、报价交期、合作记录折叠展示。合作等级仅从既有扩展资料的 `合作等级` 读取，未提供时显示待完善。

资源库及画像的“录入综合”是已提供六项评分按当前规则权重计算的平均值，不补零。无评估依据时不参与需求匹配；“有据综合”表示已登记依据。订单匹配仍使用原有硬性条件与品类专业评分规则，综合评分不能代替承接能力核实。

可勾选 2–4 家进行横向对比；选择只保留于当前页面，不写入数据库。真实供应商不足两家时按钮禁用。对比表展示实际资料、评分覆盖、依据、理论产能、可用产能及有效日期。

验证：`node modules/suppliers/supplier-ui.test.cjs`（UI 筛选、评分覆盖、零分、折叠资料、单位及对比；测试样本只存在于测试内存）。

生成匹配后自动展示当前需求的 1 主 3 备预览及待核实/未入选原因；预览不写入共享数据库。“采用当前匹配”保存规则推荐，“保存梯队”保存手动调整后的选择。日历展开时仅调整编辑弹窗的内部滚动，保持整月及操作按钮可见。

匹配与梯队统一呈现：需求输入区标题为“根据生产需求匹配供应商”，推荐供应商的硬性条件、评分依据及风险直接展示于主备卡片。未入梯队的候选、待核实及不满足资源收纳在同一区域的折叠列表。手动调整主备选择时同步复核，避免重复展示同一供应商；持久化字段与推荐规则不变。

供应商编辑表单的数字字段采用文本输入加数字键盘提示，避免原生 number 控件被滚轮、上下键或增减按钮误改。保存仍由 SupplierCore 执行数字、整数、非负及 0–100 范围校验，数据库字段类型保持不变。
